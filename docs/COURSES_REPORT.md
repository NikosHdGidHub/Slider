# Курсы в «Атласе уроков»

## Работа с библиотекой

Курсы появились в «Моих методичках» как одноуровневые папки. Корень показывает курсы и отдельные методички. В открытом курсе видны путь к папке, число доступных занятий и команды управления. Галерея и компактный каталог используют общие карточки библиотеки. Поиск в корне находит методички из всех курсов и показывает их расположение. Поиск внутри папки использует её список.

Можно создавать, переименовывать, перекрашивать, переставлять и удалять курсы. По одной команде можно переместить одну или несколько методичек, включая перемещение в новый курс или обратно в корень. Удаление папки освобождает её методички без изменения UUID, черновиков и публикаций. Методички, созданные, импортированные или дублированные в курсе, добавляются в конец. Та же последовательность действует при создании из шаблона через меню курса.

Режим «Изменить порядок» поддерживает перетаскивание за маркер и кнопки со стрелками. Поиск приостанавливает перестановку. Номера занятий вычисляются для интерфейса. При изменении порядка доступных документов позиции скрытых занятий сохраняются. Сортировка, поиск и открытый курс запоминаются. Позиция прокрутки сохраняется отдельно для корня и каждой папки в пределах сессии вкладки.

## Хранение и безопасность

| Хранилище | Данные |
| --- | --- |
| IndexedDB, `libraryCourses` | Запись на владельца с последней ревизией, очередью команд, отложенным запросом и сведениями о конфликте. Создание черновика в курсе и запись его принадлежности выполняются одной транзакцией. |
| `atlas_courses` | Папки, названия, цвета, позиции и даты. |
| `atlas_course_lessons` | Позиция и курс для UUID методички. Составной внешний ключ проверяет владельца и удаляет связи с удалённой папкой. |
| `atlas_course_revisions` | Ревизия метаданных владельца, которая проверяется под блокировкой строки. |
| `atlas_course_requests` | Квитанции по UUID запросов для безопасного повтора после разрыва соединения. |
| `atlas_course_access` | UID преподавателя, которому доступны RPC. |
| Supabase Storage и действующее хранилище методичек | Публикации, ресурсы и черновики остаются по прежним адресам и ключам. |

RLS включена на всех новых таблицах. Прямое чтение папок и связей фильтруется по владельцу. Запись доступна через RPC с проверкой `auth.uid()` и ожидаемого владельца. Функции используют фиксированный `search_path`, права выполнения выданы `authenticated`. Позиции и связи проверяются ограничениями базы. Миграция работает отдельно от Storage.

Локальные команды сохраняются до отправки. Сервер принимает весь набор изменений одной транзакцией, когда совпадает ревизия. Клиент повторяет неопределённый запрос с тем же UUID и удаляет из очереди только подтверждённую часть. Изменения разных папок и независимые правки полей по возможности объединяются. Несовместимые команды остаются на устройстве, пока преподаватель не выберет «Применить мои изменения» или «Принять облачную версию». Во втором случае приложение просит подтвердить замену локальной очереди. Изменения структуры между вкладками распространяются через BroadcastChannel.

Список объединяет документы по UUID. Методичка с местным черновиком и публикацией показана одной карточкой. Копия публикации, удалённая с устройства, остаётся доступна по сети в той же папке. После снятия с публикации показ по сети прекращается, а доступный черновик остаётся в курсе. Связи с черновиками, существующими только на другом устройстве, сохраняются без пустых карточек. Курс доступен офлайн вместе с ранее сохранёнными методичками.

## Проверки

- **Сборка и тесты Node.js.** Прошли TypeScript, production-сборка, 27 тестов, включая существующие проверки типографики и инструкций для ИИ. Новые тесты покрывают уникальность связи, массовое перемещение, удаление, сохранение скрытых позиций, объединение правок, разрешение конфликта и обработку поздней квитанции.
- **SQL в PostgreSQL через PGlite.** Два последовательных запуска миграции поверх действующих схем и политик. Проверены неизменность записей публикаций, RLS, прямые операции анонимного и постороннего пользователей, изоляция двух разрешённых владельцев, подмена UID, ссылка на чужую или отсутствующую папку, откат, каскад связей, повтор запроса, сравнение ревизий и атомарная запись порядка. Контрольный прогон записи и чтения 50 курсов и 500 связей занял 75 мс в изолированной базе. Это измерение не включает сетевую задержку.
- **Chromium с Playwright.** Пройдены сценарии старой библиотеки, создание трёх курсов, отдельное и массовое перемещение, корневой и вложенный поиск, пустая и заполненная папка, ручная сортировка и перетаскивание в обоих видах, перестановка стрелками на сенсорном экране, создание из шаблона, импорт, дублирование, восстановление поиска и прокрутки, переименование, выбор цвета, удаление непустой папки и автономная работа. Проверены окна от 360×640 до 2560×1440, включая все восемь размеров из ТЗ. Масштаб 125% и 150% задан через настройки Chromium.
- **Chromium с контролируемым Supabase API.** Два независимых профиля синхронизировали курсы, восстановили квитанцию после потери ответа и разрешили конфликт офлайн-переименования. Проверены отсутствие миграции, независимость порядка от загрузки JSON, сохранение скрытой связи и единичная карточка при наличии двух копий. В том же сценарии прошли открытие старой публичной ссылки, сохранение облачной методички, публикация, обновление, загрузка новой версии, диалог выхода с черновиком, снятие с публикации и переход в библиотеку файлов.
- **Регрессии интерфейса.** Сценарии существующих библиотек и редактора прошли в Chromium. В них проверены предпросмотр, шаблоны, генераторы инструкций, редактирование и сохранение, импорт и экспорт, заметки, проектор и офлайн-показ. Облачная часть регрессионного сценария использует контролируемый API.

Тесты выявили дублирование идентификатора во входных данных, которое мог пропустить условный UPSERT при совпадении первой записи. Добавили отдельную проверку дубликатов до изменения таблиц. На ширине 360 px инструменты библиотеки выходили за границу строки. После переноса инструментов на следующую строку горизонтальная прокрутка отсутствует в проверенных размерах. На узких экранах заголовок курса занимает всю строку. При перестановке карточки сохраняют контраст, а перетаскиваемая карточка выделяется отдельно.

```sh
python tests/courses_browser.py --cloud-only --cloud-dist /tmp/atlas-courses-cloud
python tests/library_browser.py --cloud-only --cloud-dist /tmp/atlas-courses-cloud
```

## Применение и границы проверки

Владельцу нужно применить миграцию в SQL Editor с UID преподавателя и проверить два профиля и гостевую публикацию на целевом проекте. Рабочая Supabase не использовалась. Проверки браузера выполнены в Chromium и его эмуляции сенсорного устройства. Проверку Supabase Auth и PostgREST в рабочем проекте нужно выполнить после применения миграции. [Инструкция установки](SUPABASE_SETUP.md#курсы-преподавателя) · [SQL-миграция](../supabase/courses.sql)

Перемещение между папками выполняется через диалог. Перетаскивание предназначено для изменения порядка. Холодная загрузка облачных карточек читает JSON публикаций, которые отсутствуют локально, до четырёх одновременно. Ручная перестановка использует только метаданные, без повторной загрузки этих JSON.
