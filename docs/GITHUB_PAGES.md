# Публикация на GitHub Pages

Потребуются аккаунт GitHub, Git и Node.js 22.12 или новее с npm. Для GitHub Free создайте публичный репозиторий. Исходный код и значения клиентских переменных будут видны посетителям. Сначала настройте администратора, buckets и политики доступа по [инструкции Supabase](SUPABASE_SETUP.md).

## 1. Проверьте проект локально

Распакуйте архив. Откройте терминал в каталоге, где лежат `package.json`, `package-lock.json` и скрытый каталог `.github`. Создайте копию `.env.example` с именем `.env.local`. Впишите URL проекта, публичный ключ и UUID администратора из Supabase.

```sh
npm ci
npm run dev
```

Откройте адрес из терминала, войдите и создайте методичку. Остановите dev-сервер сочетанием Ctrl+C. Для проверки итоговой версии выполните следующие команды.

```sh
npm run build
npm run preview
```

Откройте адрес preview. Vite создаёт в `dist/` весь статический сайт и Service Worker. В режиме разработки Service Worker выключен. Параметр `base: './'` в `vite.config.ts` сохраняет работоспособность путей под префиксом репозитория. Маршрут публичной презентации передаётся через адрес стартовой страницы, поэтому серверу Pages не нужны правила перенаправления.

## 2. Создайте репозиторий и добавьте исходники

1. На GitHub нажмите **New repository**, задайте имя, выберите **Public**. Создайте пустой репозиторий без README.
2. В терминале, в каталоге проекта, выполните команды ниже. Замените OWNER и REPO своими значениями. Перед коммитом проверьте вывод `git status`. Файл `.env.local` и другие локальные ключи должны быть исключены из коммита. Включите `.env.example`, `package-lock.json` и `.github/workflows/pages.yml`.

```sh
git init -b dev
git add .
git status
git commit -m "Добавить Атлас уроков"
git remote add origin https://github.com/OWNER/REPO.git
```

## 3. Включите автоматическую публикацию

1. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
2. В **Settings → Secrets and variables → Actions → Variables** нажмите **New repository variable** для каждого значения. Имена должны точно совпадать с файлом окружения.
   
   | Имя | Значение |
   | --- | --- |
   | `VITE_SUPABASE_URL` | Project URL |
   | `VITE_SUPABASE_ANON_KEY` | Publishable key или публичный ключ anon |
   | `VITE_ADMIN_UUID` | UUID созданного администратора из Authentication → Users |

3. Выполните `git push -u origin dev`. Откройте **Actions → Deploy Pages**. Первая задача устанавливает пакеты, собирает сайт и передаёт каталог `dist`. Вторая публикует его. При ошибке откройте журнал красного шага. Если Pages отвечает 404 при первом деплое, проверьте настройку Source и повторно запустите workflow.
4. Дождитесь зелёной отметки и откройте URL из задачи **deploy** или **Settings → Pages**. У проектного сайта вид адреса — `https://OWNER.github.io/REPO/`. Для репозитория `OWNER.github.io` сайт доступен в корне домена. Открывайте адрес с конечной косой чертой. Укажите этот адрес в настройках Site URL Supabase.

## 4. Проверьте установленный сайт

1. Войдите как администратор, создайте два слайда, добавьте изображение и заметки. Обновите страницу и откройте методичку. Опубликуйте её, откройте ссылку в приватном окне и переключите слайд.
2. В обычном профиле откройте **DevTools → Application → Manifest** и **Service Workers**. В manifest должны отображаться обе иконки, а активный worker должен иметь scope каталога сайта. В меню Chrome или Edge выберите установку приложения, если браузер её предлагает.
3. Откройте локальную методичку и выполните действие **Подготовить к офлайн-показу**. Дождитесь подтверждения. В **DevTools → Network** включите **Offline** и перезагрузите эту вкладку обычной кнопкой обновления. Проверьте слайды, изображения, заметки и редактирование, затем включите сеть. Для проверки нового окна с проектором отключите сеть на устройстве целиком.
4. Приватное окно, другой профиль или другой адрес имеют независимое хранилище. Сохраняйте резервную копию через экспорт JSON. Очистка данных сайта может удалить и черновики, и офлайн-кеш.

## 5. Выпускайте обновления

После изменений выполните локальную сборку, сделайте коммит и отправьте его в `dev`. Для сборки после изменения переменных откройте **Actions → Deploy Pages → Run workflow → dev**. Переменные Vite встраиваются во время сборки. После успешной публикации откройте сайт онлайн и перезагрузите его, чтобы получить новую версию Service Worker. Перед занятием повторите подготовку к офлайн-показу.
