# Архитектура и ограничения

## Документ и редактор

React и TypeScript работают на клиенте. Vite выпускает статические файлы. Deck версии 1 включает UUID, название и упорядоченные слайды. Каждый слайд содержит цвет, необязательное фоновое изображение, объекты и заметки. Координаты и шрифт заданы в виртуальных пикселях 1280 × 720. Stage пересчитывает масштаб по ширине контейнера. Один компонент рисует редактор, миниатюры и оба экрана показа. Компоненты и data model находятся в src.

IndexedDB хранит запись документа вместе с номером ревизии. Записи изменений выполняются по очереди. Транзакция сравнивает текущую ревизию с ожидаемой. При конфликте двух вкладок интерфейс сообщает об ошибке и сохраняет возможность экспортировать текущую работу. Одновременное редактирование одной методички в нескольких вкладках не предусмотрено. Объём хранения зависит от квоты браузера. Для больших коллекций изображений возможны задержки при загрузке библиотеки и автоматическом сохранении.

## Изображения и JSON

Локальный черновик хранит загруженные изображения как растровые data URL. Декодирование, уменьшение длинной стороны до 1920 px и подбор более компактного представления выполняются в браузере. Статический SVG растрируется через изолированное изображение. Импортированный текст выводится React как текст. Текущие лимиты составляют 16 МиБ на входное изображение, 64 МиБ на JSON, 1000 слайдов и 500 объектов на слайд.

После вставки изображения приложение пытается загрузить его в Storage при наличии сети и настроенного облака. Локальная копия остаётся в документе. SHA-256 позволяет повторно использовать тот же облачный файл на устройстве. Публикация повторяет неудавшиеся загрузки и записывает отдельный JSON с URL изображений. При удалении объекта из слайда облачный файл сохраняется для других занятий. Владелец может удалять ненужные файлы через Storage в Supabase Dashboard после проверки ссылок на них.

Импорт присваивает копии новый UUID документа, чтобы исключить перезапись существующего черновика и публикации. Экспорт сохраняет встроенные данные или публичные HTTPS-ссылки. Для автономной работы внешнему серверу изображений требуется разрешить CORS. Недоступные изображения помечаются на слайде. Конфиденциальные изображения и заметки нельзя включать в публикацию: JSON и файлы публичных buckets доступны любому, кто знает адрес.

## Доступ и показ

Клиент проверяет UID сессии для интерфейса, а Supabase проверяет RLS при операциях с облачными объектами. Для локальной офлайн-работы браузер помнит предыдущий вход владельца. Это доверенный профиль браузера; любой человек с доступом к его файлам может читать локальные черновики. Для общего компьютера используйте отдельный профиль ОС или браузера. Публичный просмотр запрашивает актуальную версию по UUID без локального кеша публикаций. Сохранённые ранее копии у зрителей отозвать невозможно.

Проектор использует отдельное окно того же браузера и React portal. Оба экрана получают индекс текущего слайда из одного состояния. Требуются разрешение всплывающих окон и расширенный рабочий стол. Внешний монитор и мобильные браузеры могут обрабатывать полноэкранный режим по-разному.

## Офлайн и размещение

Service Worker перехватывает только ресурсы сборки в своём scope. Публикации и запросы Supabase проходят в сеть. Подготовка к офлайн-показу проверяет кеш оболочки, скачивает внешние изображения, декодирует все изображения и сохраняет документ в IndexedDB одной транзакцией. Сбой на любом этапе выдаёт сообщение об ошибке. Браузер может удалить локальные данные при нехватке места или очистке истории. Нужны резервные копии JSON.

Относительные пути ресурсов и hash-маршрут #p/UUID работают в подпапке GitHub Pages. Собственного сервера или пользовательских таблиц БД нет. Настраиваемые параметры Supabase встраиваются во время сборки. Для выхода в интернет требуется HTTPS. Установка PWA и офлайн-оболочка доступны в production-сборке.
