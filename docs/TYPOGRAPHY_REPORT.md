# Типографика и формат v4

Работа выполнена в ветке `style-new-text` от `main` на коммите `7cf5321a0eb1b09464834626a86fcaeb41f9194e`.

## Модель и редакторы

Колонтитулы раньше читались из нескольких источников. Правка ячейки могла быть перекрыта значением презентации, значением слайда или текстовым объектом. Индивидуальные стили ячейки и объекта также перекрывали друг друга. На холсте можно было править только отдельный фрагмент. Для произвольного выделения приходилось вручную разбивать текст в инспекторе.

- **Структура** хранит схемы, размеры, отступы сетки и стабильные ID ячеек. Главный шаблон задаёт три схемы. Компоновка добавляет одну внутреннюю сетку. При применении главного шаблона методичка получает его системные стили, а при применении компоновки сохраняет свои. Именованные стили и файлы гарнитур копируются с разрешением конфликтов ID.
- **Типографика** хранит семь обязательных системных стилей в `theme.systemStyles`. Дополнительные стили находятся в `theme.styles`. Заголовки, подзаголовки, описания, колонтитулы и подписи используют системный стиль типа. Для `text` возможны именованный стиль и локальные свойства. При удалении именованного стиля ссылки обновляются в ячейках, объектах и закреплённых слоях.
- **Содержание** использует `cell.value` как исходный текст и объект с `slot` как собственное значение слайда. Пустая строка на слайде остаётся пустой. Сброс в шаблоне возвращает имя типа, сброс в методичке восстанавливает исходный текст сохранённой копии. Массовая команда записывает значения в совпадающие ячейки текущего шаблона.
- **Визуальное редактирование** использует ProseMirror для цельного блока и диапазонов выделения. В хранимой структуре фрагмент содержит явно заданные свойства. Поле `text` выводится из абзацев и проверяется при чтении. Вставка принимает простой текст. Отмена и повтор используют историю документа.
- **Оформление** использует один расчёт для холста, миниатюр, импорта, преподавателя и проектора. Панель содержит горизонтальное и вертикальное выравнивание, межбуквенные и межстрочные интервалы, интервалы после абзаца, четыре отступа, автоподгонку и эффекты. Слои шаблона показывают закрепление, блокировку и роль декора отдельными признаками.

## Миграция

Валидатор сначала проверяет исходную структуру v1, v2 или v3. После преобразования тот же документ проходит проверку v4. Контейнеры с `format: 3` получают `format: 4`. Старые контейнеры свободного размещения без сеточной структуры читаются через совместимый путь.

В старой ячейке приоритет имел размещённый объект, затем индивидуальное значение слайда, затем общее значение и исходный текст ячейки. Миграция сохраняет этот порядок. Общее значение становится исходным текстом соответствующей ячейки, индивидуальное становится собственным объектом слайда. Различие между пустой строкой и отсутствующим значением сохраняется.

Первое оформление типа в порядке титульной, обычной и завершающей схем задаёт системный стиль. Отличающиеся ячейки получают именованный стиль и тип `text`. Поле `bindingType` сохраняет прежнюю семантику маршрутизации. В конструкторе она подписана у ячейки. Старые фрагменты, отступы и списки сохраняются. Новые ID для конфликтующих стилей и переносимых текстов вычисляются детерминированно.

IndexedDB хранит исходник перед первой перезаписью старой записи. Команда в карточке скачивает резервный JSON. Ошибка преобразования локального файла оставляет оригинал в хранилище с возможностью скачать его из списка ошибок. Старые публичные документы преобразуются при чтении. Облачный документ меняется при явном сохранении.

## Шрифты и офлайн

Добавлены Inter, Golos Text, Manrope, Montserrat, Roboto, Open Sans, Nunito, Rubik, PT Sans, PT Serif, Lora, Playfair Display, Cormorant Garamond, Unbounded, Oswald, Rubik Mono One, JetBrains Mono и IBM Plex Mono. DejaVu Sans, Serif и Sans Mono получили реальные обычные, полужирные и курсивные начертания в WOFF2. Системный Arial используется для совместимости со старыми файлами.

Дистрибутив содержит 197 файлов WOFF2 общим размером 6 589 480 байт. Добавленные семейства распространяются под SIL Open Font License 1.1. Для DejaVu действуют лицензия Bitstream Vera и условия, указанные в приложенном файле. Лицензия лежит рядом с файлами каждого семейства. Каталог построен по метаданным и Unicode-диапазонам Fontsource. [Гарнитуры и лицензии](../public/fonts)

В основной кеш входят три семейства DejaVu, всего 2 011 476 байт шрифтов. Дополнительные семейства загружаются при показе. Подготовка методички проверяет наличие всех файлов задействованных семейств в отдельном кеше. Ключи с хешами позволяют повторно использовать шрифты при обновлении оболочки. Полная сборка выросла примерно с 1,33 до 8,00 МБ. Сжатый основной JavaScript занимает около 290 КБ. Пользовательские шрифты по-прежнему включаются в JSON документа.

## Инструкции для ИИ

Выбор остаётся в меню конкретной карточки главного шаблона. Для нового шаблона презентации и для компоновки используются отдельные инструкции с формальной схемой нужного корня. Из выбранного шаблона включаются его содержимое, оформление, ID, геометрия, исходный текст и правила редактирования каждого слота. Справочник добавляет доступные гарнитуры, начертания и насыщенности. Обе инструкции описывают также композицию, читабельность и проверку результата. Схема компактизирована удалением повторяющихся описательных аннотаций. Проверочные ограничения сохранены.

## Проверки

- **Node.js** проверяет чтение v1–v3, идемпотентность, приоритет исходного и собственного текста, в том числе пустой строки, сохранение старого оформления и фигур, строгие типы, разрешение конфликтов стилей при компоновке, реальные WOFF2 и инструкции. Контрольные JSON импортируются через те же валидаторы, что и в приложении.
- **Chromium с Playwright** проходит сценарии конструктора, массовой замены, редактирования строгой ячейки, выделения и форматирования, отмены и повтора, оформления, проектора и автономного показа. Проверены окна 1024×600, 1280×720, 1366×768, 1440×900, 1920×1080 и 2560×1440. Проверка таблиц знаков подтвердила полный русский алфавит, включая Ё и ё, в 59 файлах кириллических начертаний. Регрессионный сценарий библиотек проверяет также телефонный просмотр, ограничение редактора, импорт прежних документов и пользовательские шрифты.
- **Облачные сценарии в Chromium** используют тестовые HTTP-ответы: видимость и ревизия карточек, сохранение шаблона, скачивание инструкции из локальной версии, чтение публикации после удаления её локальной копии.
- **Визуальная проверка** выполнена по снятым в Chromium кадрам. Исходный файл «Vertex — студия 3D.atlas.json» отсутствовал среди приложенных файлов и в репозитории. Для проверки использован самостоятельный макет с указанными в задании надписями, кубом и разными размерами заголовков.
- **Ограничения проверки**. Совместимость проверена в Chromium на Linux. Действующий проект Supabase, физические планшет, macOS и проектор не участвовали. Примеры JSON подготовлены и валидированы здесь, внешняя модель отдельно не запускалась. Отдельный компактный формат передачи только содержимого оставлен для последующей работы с версионированным снимком шаблона.
