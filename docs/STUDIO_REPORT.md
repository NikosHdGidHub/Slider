# «Атлас уроков». Редактор и формат 2

Работа выполнена в существующем приложении React, TypeScript и Vite на базе коммита `c3074f4`. Центральный сценарий проверен в Chromium. Учитель скачивает инструкцию из библиотеки, импортирует JSON с предпросмотром, меняет текст и фигуры, экспортирует презентацию и повторно открывает результат.

[Пример инструкции со встроенным каталогом](examples/atlas-instructions.txt) · [Полный JSON «Круговорот воды в природе», 5–6 лет](examples/water-cycle.json) · [Пять снимков слайдов после импорта](examples/slides)

## Формат, текст и графика

Корень документа содержит `version: 2`, UUID, название, холст 1280 × 720, тему с палитрой и именованными стилями, ресурсы шрифтов и слайды. Каждый слайд хранит цвет, фоновое изображение, заметки и упорядоченные объекты. Встроенные стили и геометрия переходят в копию целиком. Удаление шаблона сохраняет оформление созданных уроков. При импорте в библиотеку копия получает отдельный UUID презентации. Идентификаторы слайдов и объектов, их содержимое и порядок сохраняются.

В импорте JSON, чтении IndexedDB и гостевом показе используется один валидатор. Он проверяет версию, схему, диапазоны, уникальность ID, ссылки на стили, типы встроенных файлов и ограничения контуров. В структурной ошибке указывается путь до свойства с индексом слайда и объекта. Чтение старого документа сохраняет исходные координаты, текст, изображения, заметки и исходный порядок. Для текста v1 выставляются прежний системный Arial и исходный кегль без автоматического уменьшения. Проверка включала старую базу IndexedDB версии 1 с существующим черновиком.

Текст хранится как обычная строка и, при разном оформлении фрагментов, как абзацы с массивами `runs`. Строка должна совпадать с текстом этих абзацев. В одном блоке доступны разные гарнитуры, кегли, начертания, цвет, маркер, списки и интервалы. Один и тот же компонент выводит надписи в тексте и фигурах. Двойной щелчок по фрагменту открывает ввод на холсте. В инспекторе можно выделить фразу, создать отдельный фрагмент и изменить его свойства.

Общие стили хранятся в теме. Параметры применяются последовательно от значений объекта к именованному стилю, затем к индивидуальным значениям и фрагментам. Поэтому можно, например, сохранить собственный цвет заголовка при смене общего шрифта. Автоподгонка измеряет содержимое в DOM с фактическими переносами, отступами и метриками гарнитуры. Она выбирает кегль до заданного минимума и пересчитывается при загрузке шрифта. При дальнейшем переполнении в редакторе и предпросмотре появляется сообщение. Изменение размера рамки восстанавливает исходный кегль, если места достаточно.

В поставку входят DejaVu Sans, Serif и Sans Mono с кириллицей. Лицензия включена в публичную сборку. Редактор проверяет расширение, размер до 4 МиБ, сигнатуру и декодирование пользовательского WOFF2, WOFF, TTF или OTF. Загруженный файл получает ID на основе SHA-256. Его можно применить к тексту, фрагменту и общему стилю. Байты ресурса сохраняются с уроком или шаблоном. При публикации редактор запрашивает подтверждение права на распространение шрифта. При отсутствии файла импорт пытается восстановить ресурс по ID из доступной библиотеки, затем использует резервную гарнитуру и предупреждает о замене.

Поддерживаются прямоугольник, скруглённая карточка, круг, эллипс, треугольник, шестиугольник, звезда, стрелка, прямая, ломаная, кривая и собственный контур. Узлы и ручки кубических кривых можно перемещать на холсте. Фигура хранит собственный Rich Text. Объект можно перемещать, изменять в размерах, поворачивать, отражать, менять его слой и непрозрачность. Доступны сплошная и прозрачная заливка, линейный и радиальный градиенты, цветовые точки, тени, контуры и пунктир.

При импорте SVG применяется список разрешённых элементов и атрибутов. Поддерживаются простые группы, примитивы и один путь с командами M/L/H/V/Q/C/Z в абсолютных и относительных координатах. Поддерживаемые пути превращаются в редактируемые узлы. Внешние ссылки, события, CSS, фильтры, SVG-трансформации и неподдерживаемые команды дают явную ошибку. Для фона поддерживаемый SVG проходит ту же проверку и сохраняется растровым изображением.

## Шаблоны и обмен с моделью

В боковом меню находится раздел «Шаблоны» с вкладками «Презентации» и «Компоновки». В поставке две темы и три компоновки. Встроенный вариант можно просмотреть, экспортировать или открыть как личную копию. Пользовательские записи можно создавать визуально, импортировать, переименовывать, копировать и удалять. В редакторе шаблона можно менять количество и порядок слайдов. Сохранение требует ровно трёх страниц для презентации и одной для компоновки.

При выборе компоновки на обычном слайде редактор запрашивает подтверждение замены уже заполненного содержимого. Фон, декоративные объекты, тема и заметки сохраняются. Объекты компоновки масштабируются по рекомендуемой области. Новые записи сначала сохраняются в IndexedDB. Владелец может загрузить шаблон в частную таблицу Supabase. При чтении облачная копия кешируется на устройстве. Запись сверяет ревизию, чтобы обнаружить параллельное изменение.

**Кнопка «Скачать инструкцию для ИИ» расположена в заголовке «Мои методички» и раздела «Шаблоны».** Перед скачиванием приложение читает актуальный каталог. В UTF-8 файл входят версия, используемая валидатором формальная схема, геометрия шаблонов, обе библиотеки, стили, сведения о шрифтах, рекомендации по композиции и четыре полных эталонных документа. Генератор проверяет эталоны реальным валидатором. Для офлайн-каталога указывается область доступности. Схема и эталонный скачиваемый файл проверяются автоматическими тестами.

В инструкцию попадают данные дизайна и метаданные гарнитур. Приложение пытается встроить доступное внешнее изображение. Если скачать его не удалось, в каталоге указывается ID пропущенного ресурса. Адреса внешних файлов и учётные данные приложения в инструкцию не передаются. Текст пользовательских шаблонов помещается в сериализованный каталог, и модели объясняется его роль. Встроенного клиента ChatGPT или DeepSeek в приложении нет.

### Повторить локально

Требуются Node.js 24, Python с Playwright и Chromium. Для проверки локальной мастерской собирайте без переменных Supabase.

```sh
npm ci
npm run build
node --test tests/*.test.mjs
python tests/browser.py
python tests/studio.py
python tests/fonts_browser.py sample.woff2 sample.woff sample.ttf sample.otf
```

Передайте последней команде пути к четырём настоящим файлам в указанном порядке. Переменная `ATLAS_CAPTURES` задаёт каталог для снимков импортированных слайдов в tests/studio.py. Фиктивные параметры отдельной облачной сборки указаны в начале tests/cloud_browser.py. После сборки передайте этому сценарию каталог её статических файлов. tests/template-policies.sql предназначен для изолированной базы с тестовыми пользователями.

## Внешняя приёмка и развёртывание

Реальные диалоги ChatGPT и DeepSeek в этом прогоне не проводились. Эталонная презентация подготовлена в репозитории. Для ручной приёмки откройте независимый новый чат в каждой модели, приложите скачанный из приложения atlas-instructions.txt и отправьте запрос «Создай наглядную презентацию о круговороте воды для детей 5–6 лет. Выбери подходящий шаблон и верни готовый JSON». Сохраните исходный ответ каждой модели. Импортируйте его через предпросмотр, проверьте все слайды и декор, измените подпись в фигуре, экспортируйте и снова откройте результат. Отдельно запишите ошибки первого ответа и изменения, которые понадобились для успешного импорта.

Рабочий Supabase владельца, выполнение GitHub Actions после слияния и физический проектор остаются этапами внешней приёмки. Владелец сверяет UID в миграции и применяет её в SQL Editor. Затем проверяет приватный шаблон во втором профиле и публикацию урока в гостевом окне. Для развёртывания используются существующий Pages workflow и переменные VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY и VITE_ADMIN_UUID. [Настройка Supabase](SUPABASE_SETUP.md) · [Развёртывание Pages](GITHUB_PAGES.md)
