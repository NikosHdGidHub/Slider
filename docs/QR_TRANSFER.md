# Передача публичной методички по QR-коду

В «Опубликованных» компьютер открывает экран ожидания. Одноразовый QR-код ведёт на мобильный экран того же сайта, включая подпапку GitHub Pages. Телефон показывает код устройства, запрашивает вход при необходимости и предлагает выбрать одну действующую публикацию. Компьютер получает UUID и ждёт нажатия «Открыть методичку». На экране результата можно скопировать ссылку или показать отдельный QR-код для учеников с адресом вида `#p/UUID`.

## Секреты, права и время ожидания

Браузер генерирует два независимых 256-битных секрета через Web Crypto. В базе сохраняются SHA-256. Ссылка в QR-коде содержит UUID запроса и секрет отправителя во фрагменте URL, который браузер не отправляет с HTTP-запросом страницы. Секрет получателя хранится в памяти вкладки и отправляется только в запросах к Supabase. Код из шести символов нужен для визуальной проверки устройства. Преподаватель подтверждает совпадение на телефоне.

Гостевые операции выполняются через отдельный клиент Supabase с публичным ключом и без сохранения сессии. RPC отправки проверяет JWT через роль и UID Supabase и сверяет переданный UUID с объектом в публичном бакете presentations. Телефон обращается к Supabase со своим JWT. Компьютеру сервер возвращает статус и, при получении, только UUID. Название загружается отдельно из той же публичной методички, которую может открыть ученик.

Таблица находится в закрытой схеме с RLS. Клиентские роли не имеют доступа к строкам. Ограниченные RPC сравнивают хеш соответствующего секрета. Отправка и получение блокируют строку запроса и меняют её состояние в рамках одной транзакции. При получении или отмене UUID удаляется из записи. При снятии с публикации до доставки сервер отказывает в получении.

Запрос действует не более 120 секунд. Компьютер проверяет его примерно раз в 2,3 секунды только на экране ожидания. Сервер устанавливает двухсекундный интервал для ожидающей записи. Создание ограничено 60 запросами за минуту на проект и 12 за минуту для адреса, если шлюз передаёт его. Общий предел действует независимо от заголовков. Создание следующего запроса удаляет просроченные строки. При отсутствии новых запросов оставшиеся строки ограничены лимитом, а их содержимое недоступно через RPC. Обрыв соединения после того, как сервер отметил ссылку полученной, требует нового QR-кода.

## Изменённые файлы

- `src/TransferScreen.tsx` и `src/transfer.ts` реализуют экраны, генерацию QR-кодов, отдельные секреты и запросы к Supabase.
- `src/main.tsx`, `src/cloud.ts` и `src/style.css` подключают экраны к разделу публикаций, входу, гостевому просмотру и стилям приложения.
- `supabase/qr-transfer.sql` содержит миграцию. UID внутри owner_allowed должен совпадать с VITE_ADMIN_UUID. [Порядок развёртывания](SUPABASE_SETUP.md#передача-методички-по-qr-коду)
- `package.json` и `package-lock.json` добавляют генератор `qrcode`. В разработке используются `@types/qrcode`, `@electric-sql/pglite`, `jsqr` и `pngjs`.
- `tests/transfer.test.mjs`, `tests/transfer-db.mjs` и `tests/transfer_browser.py` проверяют миграцию, разрешения, обмен и визуальные QR-коды.
- `docs/USER_GUIDE.md` и `docs/SUPABASE_SETUP.md` содержат шаги использования и настройки.

## Результаты проверок

- Production-сборка и все 27 тестов Node прошли. Пять новых тестов применяют миграцию дважды и проверяют права владельца, гостя и другого пользователя, разделение секретов, лимиты, истечение, очистку и единственного получателя при повторных запросах.
- Прошли семь браузерных сценариев. Новый сценарий использует три независимых профиля Chromium. Он проверяет вход телефона после сканирования, доставку только выбранному компьютеру, остановку опроса, отмену и возврат сети у второго компьютера, копирование ссылки и публичный показ без сессии преподавателя. Оба QR-кода декодированы со снимков экрана. У телефона проверен выбор урока при ширине 360 пикселей.
- Для медленного соединения отсчёт срока на клиенте начинается до сетевого запроса. Это исключает продление ожидания на длительность запроса. Изображение QR загружается отдельным модулем по запросу, чтобы не увеличивать основной пакет генератором.

## Как повторить проверки

```bash
npm run build
node --test tests/*.test.mjs
VITE_SUPABASE_URL=https://atlas-test.supabase.co \
  VITE_SUPABASE_ANON_KEY=sb_publishable_fixture \
  VITE_ADMIN_UUID=43649fda-26cb-4b20-bbc1-0a398e9d8ce3 \
  ./node_modules/.bin/vite build --outDir /tmp/slider-transfer
python tests/transfer_browser.py /tmp/slider-transfer
```

Браузерный сценарий использует Playwright и Chromium. Операции RPC выполняет изолированный PostgreSQL в PGlite с данной SQL-миграцией. Тестовый шлюз имитирует Supabase Auth и публичный Storage. Испытание рабочего шлюза и сканирование физической камерой требуют отдельной проверки после развёртывания.
