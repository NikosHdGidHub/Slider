# Библиотека файлов и публикации

## На устройстве

Вкладка читает существующие методички из IndexedDB. Она ищет растровые Data URL на слайдах, в фонах, нераспределённых элементах и оформлении главного шаблона. SHA-256 объединяет одинаковые байты в одну карточку со списком методичек. Новые бинарные копии для галереи не создаются. Ссылки HTTPS без встроенных байтов вынесены в подсказку об офлайн-подготовке.

Обычная вставка изображения в редакторе завершает работу в локальном документе. При выборе изображения или фона из облака редактор сохраняет оригинальные байты и проверяет лимит документа. Используется действующий формат JSON. Для облачных черновиков встроенные байты дедуплицируются по SHA-256 и хранятся в закрытом бакете `atlas-private-resources`. Файлы, используемые только в черновике, доступны владельцу.

## В облаке

Представление atlas_file_inventory перечисляет действующие объекты Storage с правами запрашивающего пользователя. Оно дополняет их именем, папкой и SHA-256 из каталога, если запись уже есть. Исторические объекты появляются сразу без загрузки или переноса содержимого. Скрытые карточки снова видны. Метаданные объекта из старого каталога восстанавливаются при переименовании, перемещении или проверке на совпадение с новым файлом. Для старых объектов имя по умолчанию берётся из пути Storage.

Файл можно загрузить через облачную вкладку. При публикации загружаются недостающие изображения из публикуемой части документа. Обе операции проверяют SHA-256 и повторно используют существующий объект. Если каталог ещё не знает SHA-256 старого объекта подходящего размера, клиент скачивает его для проверки. Уже существующие отдельные объекты с одинаковыми байтами остаются по своим адресам.

Карточки показывают миниатюры, формат, размер, дату, папку и статус публикации. Поиск, фильтры и меню действий доступны с клавиатуры. Сетка адаптируется к ширине экрана. Изображения читаются по публичным адресам, PDF, PPTX и JSON в файловом каталоге хранятся в закрытом бакете.

## Проверка ссылок и удаление

Приложение сравнивает пути объектов с адресами в действующих опубликованных JSON. Один файл учитывается один раз на публикацию. Анализ включает фон и образы главных шаблонов. Если список или JSON не удаётся прочитать и проверить, интерфейс показывает «Использование не проверено» и блокирует удаление.

После подтверждения приложение получает общую блокировку Storage и повторяет проверку по авторизованным запросам. Удаление, публикация, снятие с публикации и регистрация загружаемых ресурсов используют одну блокировку. Ограничительные политики Storage принимают изменения из приложения с действующим идентификатором блокировки. Перед записью публичного JSON проверяется доступность изображений. При удалении подтверждается отсутствие объекта в инвентаре Storage и очищается строка каталога. При сбое очистки представление всё равно отражает состояние Storage, а интерфейс сообщает об ошибке. Снятие с публикации освобождает зависимость и оставляет файл для отдельного решения преподавателя.

При удалении облачного файла также проверяются ссылки на него в доступных рабочих черновиках, шаблонах, локальных резервных копиях и в ожидающих операциях удаления. Приватный бакет черновиков защищён от физического удаления клиентом. Старые черновики, ссылающиеся на облако без локальных байтов, зависят от доступности исходной ссылки. Для них доступна «Подготовить к офлайн-показу». Проверка публикаций читает их последовательно, поэтому для большой библиотеки она может занять время. При потере ответа на запись блокировка сохраняется, чтобы другое устройство не приняло решение по устаревшему состоянию. Блокировка истекает через десять минут. Прямое администрирование Storage вне приложения требует самостоятельной проверки ссылок.

## Файлы, миграция и проверка

- Вкладки, карточки, поиск, статусы и действия находятся в `src/Files.tsx` и `src/style.css`. Точка входа страницы находится в `src/main.tsx`.
- Вставка и локальные копии реализованы в `src/Editor.tsx`, `src/Background.tsx` и `src/media.ts`.
- Инвентаризация, блокировка, анализ публикаций и запись находятся в `src/resources.ts`, `src/cloud.ts`, `src/fileUsage.ts` и `src/publication.ts`.
- Миграция `supabase/file-inventory.sql` добавляет представление, обновляет ключ метаданных и вводит политики Storage. Выполните её после `files.sql`. [Инструкция развёртывания](SUPABASE_SETUP.md#обновление-раздела-мои-файлы)
- Руководство и развёртывание описаны в `docs/USER_GUIDE.md` и `docs/SUPABASE_SETUP.md`. Архитектура обновлена в `docs/ARCHITECTURE.md`.
- Проверки облачного сценария и SQL находятся в `tests/cloud_browser.py` и `tests/file-inventory-policies.sql`.

Прошли production-сборка, 22 теста Node и 6 сценариев Chromium. Облачный сценарий проверяет локальные изображения из двух методичек после перезагрузки без сети, восстановление старых и скрытых объектов, одновременные загрузки, вставку изображения и фона, публикацию между двумя профилями, запрет удаления используемого файла и удаление после снятия публикации. При отказе Storage и недоступности опубликованного JSON объект сохраняется. Сетка проверена на ширинах 360, 768, 1280 и 1600 пикселей с длинным именем файла.

В PGlite миграция успешно применена дважды. Проверены доступ к инвентарю для владельца, запрет для гостя и другой учётной записи, исключительность блокировки и отказ Storage в политике при отсутствующем или просроченном идентификаторе. Браузерный тест использует локальный HTTP-стенд. В рабочем проекте отдельно проверьте передачу заголовка блокировки через Storage, физическое удаление пробного файла и поведение публичного CDN после удаления. [Руководство преподавателя](USER_GUIDE.md#мои-файлы)

## Каталог опубликованных методичек

Галерея публикаций и мобильная передача получают список метаданных. Список сверяется с действующими объектами Storage, поэтому снятие с публикации удаляет карточку при следующем обновлении. Полный JSON для просмотра читается по публичному адресу. Пользовательские изменения черновика отправляются в закрытую библиотеку. Операции публикации выполняются отдельно.

Для уже существующих публикаций владелец может заполнить индекс через «Индексировать прежние публикации». UUID, содержимое Storage и публичные ссылки сохраняются. [Обновление Supabase](SUPABASE_SETUP.md#облачная-синхронизация-рабочего-пространства)
